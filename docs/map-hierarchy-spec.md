# Map hierarchy and geographic references

Reviewed 2026-10-04. The data/helpers and focused tests are implemented. Map, drawer and camera integration is complete; browser/build evidence is recorded in `globe-hierarchy-verification.md`.

## Contract

`getMapNodes(filteredPlaces, kind)` accepts the **already-filtered** `TravelPlace[]`, with `kind` equal to `country` or `location`. It returns nonempty `MapNode[]`. Every node has `id`, `kind`, `label`, `[longitude, latitude]` `coordinates`, `collectionId`, `countryId`, `photos`, `photoCount`, `cover`, `precision` and `referenceLabel`. Photo objects and their input order are preserved; the first remaining photo supplies the cover. Source arrays are not mutated.

`getMapNode(id, filteredPlaces)` returns a node from either level or `null`. A leaf excluded by filters stays absent even when its country/collection still contains other photos. Keep `selectedNodeId` separate from the original collection selection. Leaf selection scopes drawer title/photos and lightbox to that node; country selection lists the country's location nodes in the drawer; a place opens its photos. Collection navigation and collection search clear the leaf scope. Invalidated leaf selection closes the drawer without selecting another location or moving the camera. Counts and covers must come from these derived nodes, never the unfiltered originals.

Locations live in `src/data/locations.json`: a tree of country, region, place and sublocation nodes (`parent` pointers, at most four levels). Each map photo's manifest entry carries the `locationId` of its deepest node. Ids are stable once published (favorites and exploration progress persist them); moving a node changes only its `parent`. `travelPlaces` is derived, one collection per country with the country node's id (`austria`, `italy`, `norway`, `united-states`); country node IDs are `country:<id>`. The United States is too large for one top-level stack, so its states stand in for it: `getMapNodes(..., "country")` returns one node per photographed state (`country:north-carolina`), `collectionId` stays `united-states`, and each US location node's `countryId` is its state node. `getCountryChildBounds` accepts those ids. Location markers are the place level (third) of each photo's path, as `location:<id>`. Sublocations are recorded but not yet drawn as markers. Where `layoutMapMarkers` cannot separate location markers at the resting camera zoom, `clusterMapNodes` (src/lib/map-marker-layout.ts) merges each same-country group into one `cluster` node (`memberIds`, summed photos, bounds-centre coordinates); clicking it fits the members' bounds. Clusters exist only in the map's drawn nodes: progress, search and selection keep the location ids. Places carry `coordinates` with a `coordinateSource`: `manual` (the evidence table below), `geocoded` (OSM Nominatim, once, at import) or `photo-gps` (rounded centroid of the photos' GPS). Regions and countries derive their position from their places.

Country photo stacks now sit at the center of the bounding extent of their **eligible verified regional children**, recomputed from the same filtered photographs. The country name groups photographs; the reference label explicitly says “photographed-region cluster reference,” never a political centroid or exact camera position. The United States stack therefore stays in North Carolina between Lake James and Raleigh (`[-80.285, 35.765]`), and Italy stays in the Dolomites (`[12.00, 46.645]`). These extra center decimals are arithmetic results from rounded regional references, not additional geographic precision. A single-child country uses that child's regional reference. IDs, photo order, covers and membership stay unchanged.

`getCountryChildBounds(countryId, filteredPlaces)` returns `[[west, south], [east, north]]` for eligible verified regional children, or `null` for an unknown country, an empty filtered collection, or a collection containing only unlocated photographs. Camera code can pass these bounds to `cameraForBounds`, providing its own viewport padding and a maximum zoom for a zero-area/single-child extent. Bounds exclude unknown-photo fallback nodes: those coordinates are not verified photo locations and would artificially widen the fit. Country stacks still count all eligible photographs; mixed known/unknown collections explicitly label that unknown photo locations were excluded from the cluster reference.

The shared `getCoordinateBounds` helper removes the largest gap on the longitude circle to obtain the shortest containing interval. Dateline-spanning bounds use an unwrapped east longitude above180 when needed (for example178…181), while country marker centers normalize into[-180,180). This avoids a nearly360° camera fit for nearby locations across the dateline. No current collection crosses it; synthetic tests cover wrapping, repeated±180 references, and input-order independence. Latitude bounds use the eligible minimum/maximum. The resulting bounds describe regional reference points, not complete photo footprints.

When no verified child remains, the country stack retains the Natural Earth country label position from `src/data/country-labels.json` (`AUT`, `ITA`, `NOR`, `USA`) and says “country reference · no verified photo locations.” Future unknown-location leaf nodes always retain that same country reference and `precision: "unknown"`, even in a mixed collection. No location is invented. Zoom threshold/hysteresis and country-to-location camera transitions remain the map implementation's responsibility.

The new Tromsø finding supersedes the uncertainty paragraph in `map-location-audit.md`: that earlier review did not have the current manifest provenance. This specification cites the public asset record by `src` and does not reproduce private source folder paths. The manifest proves curated regional membership, not EXIF GPS. The EPSG:4258/WGS84 difference is immaterial at the rounded regional precision used here.

The helper uses exact `Photo.src` membership, not fuzzy title matches, inferred image subjects, generated categories or EXIF guesses. Any future unassigned photo in a supported collection receives a separate `location:<countryId>-unlocated` node at the country label reference, with `precision: "unknown"` and an explicit unknown-location label. It is never silently assigned to Lofoten or another known leaf. Such fallback nodes and country aggregates must not count as verified locations for any later progress feature. All nine current regional nodes are distinct verified area references; no rewards are implemented here.
